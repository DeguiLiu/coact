## 评估维度（五个）

1. **信息完备性**：九类异常（U1-U9 + 花屏）每节是否自含"故障现象 → 机理 → 规避机制 → 断言证据"闭环；找出"必须翻源码才能懂"的断层点（如机制只提名字无解释、术语未定义即使用、引用的机制在其他文档但未给跳转）。
2. **一致性与准确性**：数字与全文对齐（14 AO / 7 worker / 68 断言 / ctest 53 / coro 默认构建 / 66 或 68 断言引用是否已更新）；跨文档引用的章节号（架构文档 X.Y 节、RS500 源文档章节）真实存在；抽查 3 处描述与代码行为无漂移（事务终局弧 rcGoHome 挂载、PeriphRegCache 三标志协议、DdrCtx 槽位所有权）。
3. **可读性**：术语首次出现有解释（无行话残留）；全部 Mermaid 可渲染（`tools/check_mermaid.sh` 验证）且图注自明；段落结论先行；无口语化/自造词。
4. **结构合理性**：4 章分工是否清晰（范围/事件状态/U1-U9/验证）；有无同一内容重复出现两处维护；头部"推荐阅读顺序"与实际章节是否对应；被移出的内容（编程纪律、评审裁决、AO 拓扑）在本文的残留链接是否有效。
5. **维护成本**：哪些内容会随代码演进快速过时（具体行号引用、计数清单、断言名清单），有无"以命令输出为准"类防护标注。
