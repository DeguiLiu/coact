# coact 组件价值评估

结论：coact 的价值不在 C++17，而在把事件驱动系统的执行顺序、容量上限和失败路径
变成结构约束。它适合中等复杂度、单核、要求可验证的工业控制，不适合极小固件或
需要认证 OS 的场景。

## 1. 核心价值

- 单 Dispatcher、静态 HSM、定容事件池，让“谁先执行、队列满怎么办、失败怎么回滚”
  由框架统一决定，不再依赖每个模块的约定。
- 零堆、无异常、无 RTTI，线程、队列、事件池都是静态对象，内存上限在编译期确定。
- 准入、熔断、监控、故障复位是框架的一部分，能直接产出评审需要的测试证据。

## 2. 成本

| 配置 | Flash 增量 | RAM 增量 |
|---|---:|---:|
| 默认配置 | +8.8 KiB | +9.3 KiB |
| 小配置 + LTO | +7.9 KiB | +6.3 KiB |

Dispatcher 栈为 4 KiB，本轮夹具测得历史最小剩余 978/1024 字，即 3912 B；
按填充扫描估计最大使用约 184 B。此前把高水位解释为已用空间，结论有误。
夹具调用链较浅，不能据此直接缩小产品栈；产品仍须覆盖最坏调用链和故障路径。
私有成员重排后，Cortex-M4 上 HSM 从 20 B 降至 16 B，夹具 AO 从 56 B 降至
48 B；当前单 AO 镜像因链接对齐，静态 RAM 总量不变。详见
`docs/coact_freertos_footprint_zh.md` 第 9 节。

## 3. 适用与不适用

适用：

- 多个主动对象、状态机较多、任务和 ISR 混合提交。
- 需要过载时显式拒绝而不是静默丢弃、确定性唤醒和可测的失败路径。
- 需要通过安全评审，要求无堆、故障有界复位。

不适用：

- 只有三五个任务、逻辑以顺序流程为主。
- Flash 预算低于约 64 KiB，且不需要 AO/HSM。
- 需要 AUTOSAR 保护域或功能安全认证。
