## 日志阅读指南

### 一、如何证明 #41 已解决

1. 启动行末尾会出现 `【阶段 0｜协程后端】`，说明当前执行的是 `ISP_DEMO_CORO`。
2. 运行期间 7 个 worker 共享一个 pump；没有每个 worker 对应的 pthread worker 创建日志。
3. 末尾 `worker pthreads: 0` 证明 coro 模式的单线程公平性目标成立。
4. 进程没有 `stack smashing`、`__stack_chk_fail` 或野帧，且 66 项断言全部通过。

### 二、结构化事件码

| 事件码 | 含义 |
|---|---|
| `e=1..4` | Preview Start 的 Boot、Phase1、Phase3、Phase4。 |
| `e=7` | PIC/TEMP video 命令，`s=0` 为 PIC，`s=1` 为 TEMP。 |
| `e=10` | MIPI 首帧到达 sink。 |
| `e=12` | HSM 状态迁移；`a0` 为 AO，`a2` 为信号。 |
| `e=13` | X1/X2 重配的拒绝、故障、回滚、提交阶段。 |
| `e=14` | worker 执行/拒绝统计。 |
| `e=15` | 会话状态迁移：`BOOT→INIT→RUNNING→RECFG_TXN→DEINIT→STOPPED`。 |

### 三、阶段审计锚点

- 【启动与初始化】Phase1/3/4、IRSC 四步、ISP 八节点和 PIC/TEMP 视频状态迁移。
- 【协程数据流】IRSC 产出 30 帧，经增益、打包、SOUT、MIPI/WRAPE 完成闭环；切换不同协程后仍保持各自栈和当前协程身份。
- 【运行态重配】X4 能力拒绝、DMO 全重建拒绝、X2 故障回滚、X2 干净提交四条路径均有日志和断言。
- 【T37 与一致性】记录 3 个 655360 B 提前 EOF，再验证固定几何、寄存器旁路/回灌和镜像坐标变换。
- 【停机与验收】先排空 worker，再停止 runtime；`pool.used=0` 和最终 66 个 PASS 形成闭环。
