# 编码日志与集中输出

结论：任务和 ISR 只提交事件号、来源号、计数器及整数参数，集中输出端再编码或解释。
本次复用现有 `diag::Logger`，增加可选 `CompactHexPolicy`，没有新增线程、队列或堆分配。
原有默认输出不变，`examples/log_rtthread_demo.cpp` 演示紧凑输出。

## 1. 使用方式

```cpp
using AppLog = coact::diag::LogRtThread<coact::diag::CompactHexPolicy>;
static AppLog log;

// After successful initialize() and start(), in task context:
log.record_from_task<coact::diag::LogLevel::kError, 0x0101U>(
    2U, operation_id, reason_code, target_id, pending_count);
```

生产端不构造字符串，不调用 `printf`，不保存指向临时对象的字符串指针。
ISR 使用 `record_from_isr`，不能调用初始化、等待或打印接口。
关闭前先停止生产者，再调用 `stop()` 排空队列。

`LogRtThread` 提供 RT-Thread 日志线程。FreeRTOS 可以复用平台无关的 `Logger`
和编码策略，在 BSP 现有低优先级任务中排空；本次没有新增 FreeRTOS 专用日志线程适配。
排空时限制每轮数量，避免日志积压占满 CPU；正常运行不得由 Dispatcher 同步写串口。

## 2. 输出格式

每条记录固定 56 个 ASCII 字节，含换行；编码缓冲区至少 57 B，含结尾零字符。
所有数值采用大写十六进制，不依赖目标端字节序：

```text
@12345678:0101:0002:00000007:00000003:00000001:00000008
```

| 顺序 | 字段 | 十六进制宽度 |
|---|---|---:|
| 1 | 原始计数器 | 8 |
| 2 | 事件号 | 4 |
| 3 | 来源号 | 4 |
| 4–7 | 四个原始参数 | 各 8 |

`@` 标识本版编码；字段顺序和宽度不得在同一标识下修改。
零参数、未知事件号和全部 32 位参数均保留，不通过省略字段缩短输出。
缓冲区不足时返回截断状态且不输出半条记录；RT-Thread 适配器按既有规则回退到原始格式。

与原始 `e=/s=/a0=` 格式相比，最大字段值时从 77 B 降至 56 B，减少 21 B；
小字段值时从约 60 B 降至 56 B。记录队列仍为每条 24 B，未减少队列 RAM。
详细事件说明不必每条重复打印；主机按字典还原可读文本。

## 3. 事件字典

事件号不是可随意重排的枚举序号。产品应显式赋值，并随固件归档字典：

| 事件号 | 级别 | 含义 | 参数 |
|---|---|---|---|
| `0101` | Error | 服务返回失败 | 操作号、原因码、目标号、pending |
| `0102` | Error | 保护异常 | CFSR、MMFAR、PC、LR |
| `0103` | Error | 断言触发 | 源文件号、行号、上下文号、保留 |

以上为产品分配示例，不是框架已占用的事件号。级别、参数数量、参数单位和解释来自字典，
不在每条记录中重复保存。同一事件号不得对应不同级别或不同参数语义。
未知编号仍保留原始数字，不丢弃记录。

启动时在安全的任务上下文集中输出或上报一次：固件构建标识、字典标识、
计数器频率和复位原因。32 位计数器可能回绕，解释时间差需结合频率和采集间隔；
不得将原始值直接当作毫秒。

## 4. 不丢失信息的边界

- 编码完整保留一条记录的字段，但固定容量队列不保证永不丢失。Normal 与 Critical
  分区隔离，Critical 仍可能满；必须定期汇总两类入队丢弃数、队列高水位、
  输出失败数及格式截断数。
- 关键故障应锁存首次故障或使用 BSP 保留存储；不依赖后续日志队列能够成功入队。
  不得为了日志完整而让 ISR 阻塞或在关中断区等待串口。
- HardFault、MPU 异常和 panic 先锁存故障寄存器，再完成安全输出或复位。
  禁止等待日志线程或获取它的锁；本次没有改变 BSP 的故障处置路径。
- “已排空”只表示已从队列取出，不表示串口、DMA 或上位机已收到。需要可靠传输时，
  由 BSP/传输协议定义帧校验、序号和确认机制；当前文本格式不提供这些保证。

## 5. 验证

- host 新增五项用例：固定输出、全部字段往返、短缓冲区、边界保护、任务/ISR 延迟输出与溢出计数。
- 完整 host 测试 61/61 通过；编码测试和 RT-Thread 示例通过 ASan/UBSan。
- 示例日志经独立检查，每条编码记录恰为 56 B，保留 ISR 事件；集中输出后队列统计守恒。
- Cortex-M4、GCC `-Os` 独立编码探针为 267 B text、0 B data/bss，
  无未解析外部符号，不引入 `printf`、除法或堆分配依赖。
  此数值不包含 Logger、适配线程、串口驱动或调用方缓冲区，也不是整固件节省量。
- 另用临时 Cortex-M4 镜像在真实 Renode 上检查固定记录输出和短缓冲区边界，
  UART 输出预期编码及 `LOG RESULT PASS`；这是编码冒烟测试，不是 FreeRTOS 日志线程验证，
  临时夹具未注册到仓库 CI。

本次不批量替换测试夹具的 PASS/FAIL 标记，也未转换 ISP 示例中的所有业务打印。
这些输出可能是脚本协议或演示结果，应逐处建立事件字典后迁移，不做机械替换。
